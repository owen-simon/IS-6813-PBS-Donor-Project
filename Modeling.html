Solicitation-response contribution to donor prospect ranking

Design and boundaries

This analysis predicts major_donor_next_fy for constituents whose current annual giving is below $2,000, including zero. A positive outcome is $2,000–$15,000 in the following July–June fiscal year. FY2021–FY2024 are development only: train on FY2021 and validate FY2022, then expand training through FY2022 and FY2023 to validate FY2023 and FY2024. Each validation outcome is observed in the following year. FY2025 features with FY2026 outcomes are reserved for final group testing; FY2026 is an unlabeled prediction cohort. Neither enters this analysis’s model selection, preprocessing, or evaluation. The group should freeze its choices before using the final test; FY2026 needs FY2027 outcomes.

Within each fold, compare identical models and observations with and without solicitation-response variables. Campaign response is a proxy: the source records a same-constituent, same-code payment in the fiscal year, not proven causation. Campaign start dates are year markers, not contact dates. Current and trailing features are available by year end. Snapshot attributes, cultivation assignment, IDs, split markers, and all future outcomes are excluded.

Rolling validation and imbalance

The four algorithms use fixed, modest configurations to avoid expensive tuning on rare positives. Each fold downsamples training negatives to at most five per positive, keeping all positives; validation retains its natural prevalence. A prior-odds correction maps scores back to the training population prevalence. This correction assumes sampling depends only on the outcome; calibration must still be checked. Imputation and zero-variance filtering are fitted separately inside each training fold. The same sampled records are used in both feature sets. Results are development estimates, not final-test performance.

folds <- list(`2022` = 2021L, `2023` = 2021:2022, `2024` = 2021:2023)
models <- c("Logistic regression", "Elastic Net", "Random Forest", "XGBoost")

fit_fold <- function(train, valid, features, model_name, seed) {
  set.seed(seed)
  y <- train$major_donor_next_fy
  if (length(unique(y)) != 2 || length(unique(valid$major_donor_next_fy)) != 2)
    stop("Each fold must contain both outcome classes")
  # Training-only preprocessing, before negative sampling.
  x <- as.data.frame(train[, features, drop = FALSE])
  v <- as.data.frame(valid[, features, drop = FALSE])
  medians <- vapply(x, function(z) if (all(is.na(z))) 0 else median(z, na.rm = TRUE), numeric(1))
  for (j in seq_along(x)) {
    x[[j]][is.na(x[[j]])] <- medians[j]
    v[[j]][is.na(v[[j]])] <- medians[j]
  }
  keep <- vapply(x, function(z) length(unique(z)) > 1, logical(1))
  x <- x[, keep, drop = FALSE]; v <- v[, keep, drop = FALSE]
  pos <- which(y == 1); neg <- which(y == 0)
  selected <- c(pos, sample(neg, min(length(neg), 5L * length(pos))))
  x <- x[selected, , drop = FALSE]
  sampled_y <- factor(ifelse(y[selected] == 1, "yes", "no"), levels = c("yes", "no"))
  population_prior <- mean(y == 1); sample_prior <- mean(y[selected] == 1)
  control <- trainControl(method = "none", classProbs = TRUE, allowParallel = FALSE)
  if (model_name == "Logistic regression") {
    fit <- train(x, sampled_y, method = "glm", family = binomial(), trControl = control)
  } else if (model_name == "Elastic Net") {
    fit <- train(x, sampled_y, method = "glmnet", family = "binomial",
                 preProcess = c("center", "scale"),
                 tuneGrid = data.frame(alpha = 0.5, lambda = 0.01), trControl = control)
  } else if (model_name == "Random Forest") {
    fit <- train(x, sampled_y, method = "rf", ntree = 200,
                 tuneGrid = data.frame(mtry = max(1L, floor(sqrt(ncol(x))))),
                 importance = TRUE, trControl = control)
  } else {
    fit <- xgboost::xgb.train(
      data = xgboost::xgb.DMatrix(as.matrix(x), label = as.integer(sampled_y == "yes")),
      params = list(objective = "binary:logistic", max_depth = 3, eta = 0.05,
                    colsample_bytree = 0.8, subsample = 0.8, nthread = 1),
      nrounds = 100, verbose = 0)
  }
  prob <- if (model_name == "XGBoost") predict(fit, as.matrix(v)) else
    predict(fit, newdata = v, type = "prob")$yes
  prob <- pmin(pmax(prob, 1e-8), 1 - 1e-8)
  corrected <- plogis(qlogis(prob) + qlogis(population_prior) - qlogis(sample_prior))
  importance <- tryCatch({
    if (model_name == "XGBoost") {
      z <- xgboost::xgb.importance(model = fit)
      data.frame(feature = z$Feature, importance = z$Gain)
    } else {
      z <- varImp(fit, scale = FALSE)$importance
      data.frame(feature = rownames(z), importance = rowMeans(z))
    }
  }, error = function(e) data.frame(feature = character(), importance = numeric()))
  list(predictions = data.frame(constituent_id = valid$constituent_id,
       fiscal_year = valid$fiscal_year, outcome = valid$major_donor_next_fy,
       probability = corrected), importance = importance)
}

# Average precision is the step-wise area under the precision-recall curve.
metrics <- function(d) {
  d <- d[order(-d$probability, d$constituent_id), ]
  y <- d$outcome; n <- length(y); positives <- sum(y); prevalence <- mean(y)
  precision <- cumsum(y) / seq_len(n)
  ap <- sum(precision[y == 1]) / positives
  roc <- as.numeric(pROC::auc(pROC::roc(y, d$probability, levels = c(0, 1), quiet = TRUE)))
  top <- lapply(c(.05, .10, .20), function(fraction) {
    k <- ceiling(n * fraction); p <- mean(y[seq_len(k)])
    data.frame(fraction = fraction, k = k, precision = p, lift = p / prevalence)
  })
  list(summary = data.frame(n = n, positives = positives, prevalence = prevalence,
       pr_auc = ap, roc_auc = roc, brier = mean((d$probability - y)^2),
       mean_probability = mean(d$probability)), top = bind_rows(top))
}

Interpretation and limitations

Focus on paired differences by year, especially precision and lift at realistic staff capacity. Class imbalance makes ROC AUC alone misleading. Few positive outcomes make fold metrics and importance unstable; assess uncertainty and repeatability before operational use. Importance is model-specific, not causal, and correlated giving and solicitation variables can share importance. The fixed model settings are a computational baseline, not exhaustive tuning. Random downsampling and prior correction may still produce poorly calibrated scores; temporal drift and repeated constituents across years affect evaluation. All data are synthetic, with release-specific cleaning and placeholder fields. A later final-group workflow should freeze model and features, fit on development years, and evaluate FY2025 once; FY2026 can only be scored until FY2027 labels are available. Do not interpret these results as an estimate of the causal effect of solicitation or of the cultivation program.
